# ADR-010: The context pack is a first-class per-change artifact — deterministic, hash-invalidated, injected as a stable prefix

- **Status:** proposed (moves to accepted when `context-pack-l1`'s PR merges)
- **Date:** 2026-07-24

## Context

Every dispatch of a subagent in a change's flow — the seven reviewer/dispatcher agents plus the `implement`/`review`/`ship` skills — re-reads the same durable per-change context: `proposal.md`, `design.md`, `tasks.md`, the cited ADRs, the relevant capability specs. That context is stable for the whole change, yet each dispatcher pays its full size again on every call, and the reviewers dispatched right after it pay it again on top.

The owner's own measurement (memory `aidakit-token-cost-drivers`) fixes the problem's scale: **98 % of real token cost is `cache_read`**; an 8-hour session accounts for ~61 % of a day's total; the root cause is durable context re-reading, not the flow-engine steps themselves. The PoC on 2026-07-24 (E2 of `context-pack-l1`'s brainstorm) sharpened the picture further: the SDK-level cache reuses only for the **same `subagent_type`** (~59 % of the SDK-owned prefix); every cross-type dispatch — the norm in our flow — is a complete miss. The naive assumption that "the cache handles it" is empirically false for the workload we actually run.

The mechanism to fix it must be repo-native — deterministic, byte-stable, invalidated by declared sources — because we cannot re-tune Anthropic's cache policy from inside the kit. The win we *can* engineer is **prefix-size reduction**: shrinking what each dispatch processes in the first place. That win is independent of hit-rate, so it survives whatever the SDK does upstream.

The design also has to keep the doc-leash independent of pack freshness. A stale pack is a size regression, not a missing document; conflating the two would let a stale pack block the flow at the wrong gate ([`governance/validators/check-doc-manifest.js`](../../governance/validators/check-doc-manifest.js)), which would be worse than the current status quo. So the freshness check has to be a **separate** validator from the doc-manifest one, invoked by a **separate** flow step, with a **separate** exit code contract.

## Decision

The `.context-pack.md` file, co-located under `docs/features/<change-id>/`, is a **first-class per-change artifact** with:

1. **A frozen frontmatter schema** — `change_id`, `pack_version` (integer, current: 1), `built_at_source_hash` (deterministic function of `sources[]` alone, no wall-clock), `sources[]` of `{path, sha256}` in path-sorted order. Any wall-clock, PID, tmp-path or random-id content is a **byte-stability violation** and is rejected by `governance/validators/check-context-pack.js` (this change ships that file).
2. **Six fixed sections, pointers only** — `identity`, `decisions`, `ADRs`, `specs`, `code-map-pointers`, `DoD`. Excerpts are banned: a copied paragraph drifts from its source without the source's sha256 changing, silently defeating invalidation. Pointers force the reader to open the current source on demand — the whole point of the design.
3. **A build/verify/rebuild skill** — `aidakit:context-pack` under `skills/context-pack/`. The build is deterministic: LF line endings, path-sorted sources, no wall-clock content. Rebuild is build-with-force; verify runs both validators.
4. **Hash-based invalidation scoped to declared sources** — `governance/validators/check-context-pack-freshness.js` (this change ships that file) walks `sources[]`, recomputes sha256s, exits 0 iff all match. It **never globs the repo**; a file outside `sources[]` cannot invalidate the pack (that would trip on ADR-005 edits when the pack cites only ADR-004, which is the wrong semantics for L1 — cross-change knowledge is L2's job).
5. **A dedicated flow phase** between `readiness` and `implement` in both `governance/flows/full.yaml` and `governance/flows/fast.yaml`. The phase verifies freshness and rebuilds lazily. Best-effort and fail-safe: both `on_success` and `on_failure` route to `implement`, mirroring the `commit_plan` posture from [ADR-009](ADR-009-flow-commits-plan-early.md). A build failure never blocks the flow.
6. **Read-if-present at every dispatcher, freshness upstream** — `implement`, `review`, `ship` and the six reviewer/tester agents (`aidakit:adr-reviewer`, `aidakit:spec-reviewer`, `aidakit:reviewer-quality`, `aidakit:reviewer-security`, `aidakit:reviewer-architecture`, `aidakit:tester`) READ the pack file when it exists and inject it as the stable prefix of their context. They do NOT independently re-validate freshness — freshness is guaranteed by the upstream `context_pack` `runs` phase (§5 above), which is the only place where `$AIDAKIT_GOVERNANCE` per [ADR-004](ADR-004-aidakit-governance-env-contract.md) is available. A missing pack degrades gracefully: the dispatcher falls back to reading the raw docs and completes normally. Same-`subagent_type` SDK cache reuse, when the SDK grants it, is additive on top of the size-reduction win — no dispatcher depends on it.
7. **Telemetry decoupled from the pack** — `.aidakit/tasks/<change-id>/.telemetry.jsonl` (append-only, gitignored under the existing `.aidakit/` line) records per dispatch `{ts, subagent, cache_creation, cache_read, pack_size, duration_ms, pack_rebuilt}`. The telemetry file may contain timestamps — the byte-stability rule applies to the *pack*, not to the telemetry. `aidakit:learn` rolls up the JSONL into `evidence.md` before the worktree is cleaned, so the durable evidence lives in the change dir while the raw log stays ephemeral.
8. **The freshness validator is separate from `check-doc-manifest.js`** — different file, different flow step, different exit-code semantics. A stale pack must not add a `doc-missing` finding to the doc-leash.

Injection follows the `AIDAKIT_GOVERNANCE` env contract of [ADR-004](ADR-004-aidakit-governance-env-contract.md); the new phase's command interpolates `${context.select.change_id}` inside double quotes per [ADR-006](ADR-006-flow-values-as-data.md).

L2 (embeddings, vector store, cross-change knowledge over `docs/knowledge/`, ADRs and archive) stays out of this decision, per [EPIC-context-caching](../roadmap/epics/EPIC-context-caching.md). L2 is triggered by the metrics L1 reports — not by calendar — after (a) size-reduction gain stagnates or (b) dispatches genuinely need cross-change context often enough to justify the infrastructure.

## Consequences

- **Positive:** every dispatch of the seven agents/three skills shrinks by roughly `size(proposal+design+tasks+cited-ADRs) − size(pack)`; the reduction is deterministic and does not depend on the SDK's caching behavior; the invalidation is source-scoped so a change to an unrelated ADR does not spuriously rebuild; the doc-leash and the pack-freshness gate remain independent; telemetry gives a permanent per-dispatch signal to detect regressions; the mechanism generalizes to any future flow that authors a change under `docs/features/`.
- **Negative:**
  - The pack becomes a new mandatory artifact per change — one more file to maintain, one more validator to pass — **Accepted** (the build is a single skill invocation; the validator gate is mechanical; the freshness gate never blocks the flow).
  - A new flow phase lands in both `full.yaml` and `fast.yaml`, extending their step counts — **Accepted** (the phase is best-effort and fail-safe; the additive cost is one `runs` step, mirroring the `commit_plan` shape from [ADR-009](ADR-009-flow-commits-plan-early.md)).
  - Two new validators join the `governance/validators/` set — **Accepted** (both are zero-dep, invoked via the `AIDAKIT_GOVERNANCE` contract identically to `check-doc-manifest.js`).
  - Blast radius covers every dispatcher/reviewer agent — a wiring bug on one agent could silently break the fallback path — **Mitigated** (a contract test per agent asserts both the pack-present and pack-absent behaviors; graceful degradation means the failure mode is a visible size regression in telemetry, not a broken flow).
  - The pack schema (six sections, frontmatter shape) is now a **public contract** that consumer flows depend on — future schema evolution bumps `pack_version` and requires migrating dispatchers — **Accepted** (the version field is precisely the tool for that; the current version is `1`).
  - The telemetry JSONL grows unbounded within a session — **Accepted** (the file is per-change and gitignored; `aidakit:learn` rolls it up at end-of-run and the operator is free to delete it after archiving).
  - **The dispatcher/reviewer integration relies on the upstream `context_pack` flow phase (a `runs` step with `$AIDAKIT_GOVERNANCE` in its child env) to enforce freshness. Agents/reviewers/skills do NOT independently validate the pack — they read it if present and fall back to raw docs if absent.** This split is a direct consequence of [ADR-004](ADR-004-aidakit-governance-env-contract.md) §negative-consequence-2: `$AIDAKIT_GOVERNANCE` reaches `runs`-step children only, never agent/skill Bash sessions, so an agent that shelled out to `check-context-pack-freshness.js` would either reinvent path resolution (violating the ADR-004 contract) or fail in any repo whose cwd is not the kit itself. The `agent-validator-paths` gap tracked in [EPIC-flow-engine-leashes](../roadmap/epics/EPIC-flow-engine-leashes.md) remains OPEN and explicitly OUT OF SCOPE for this change; when it lands (with whatever mechanism it chooses), the dispatchers MAY be tightened to re-check freshness independently, but the read-if-present contract shipped here stays correct because it degrades safely and does not depend on a mechanism that does not yet exist.
  - **The engine's `resume` protocol is extended additively (backward compatible) to accept usage kwargs from the parent dispatcher.** Because `governance/engine/steps/invoke.js` is IoC (pauses, asks the parent Claude to dispatch, resumes on `node governance/cli.js resume …`), the engine itself never observes the SDK response of the dispatched agent; the only place the engine can legitimately write telemetry is the resume handler, where the parent authoritatively holds the response. `governance/cli.js` gains optional `--tokens-cache-read=N`, `--tokens-cache-creation=N`, `--tokens-output=N`, `--duration-ms=N`, `--pack-rebuilt=bool` kwargs after the outcome; when present, `invoke.js` forwards them to `governance/telemetry/append.js`, which appends one JSONL line under `.aidakit/tasks/<change_id>/.telemetry.jsonl`. When absent, no line is written and the flow proceeds unaffected — every existing `resume` callsite continues to work verbatim. See `context-pack-l1`/`tasks.md` §7d–§7f for the RED/GREEN/REFACTOR breakdown. This extension does not contradict [ADR-004](ADR-004-aidakit-governance-env-contract.md) (the write happens from a `runs`-tier context — the engine process itself, not an agent Bash session) nor [ADR-006](ADR-006-flow-values-as-data.md) (kwargs are single safe tokens under the same whitelist rule as the existing structured outputs of `resume-output.js`).

### Review trigger

- If the size-reduction win stagnates (mean per-dispatch `cache_read` stops shrinking as more changes are packed) — that is L2's cue per [EPIC-context-caching](../roadmap/epics/EPIC-context-caching.md), and a superseding ADR should reframe this decision under L1+L2.
- If dispatches routinely need context from OTHER changes (the pack references start pointing outside the change dir with enough frequency to matter), same trigger — cross-change context is L2's problem, not L1's.
- If the SDK ever grants cross-`subagent_type` cache reuse, the "additive" clause becomes "primary" — revisit whether the pack's byte-stability discipline can be relaxed to allow more expressive content without losing the reuse.

## Alternatives considered

| Option | Pros | Cons | Cost to undo |
|---|---|---|---|
| Status quo — do nothing, trust the SDK cache | Zero engineering | 98 % of cost is `cache_read` (owner measurement); PoC E2 shows cross-type miss dominates; the problem stays exactly where it is | — |
| L2 embeddings-first — vector store over `docs/knowledge/` + ADRs + archive | Directly addresses cross-change knowledge reuse | No empirical data justifies the infra yet; high infra + maintenance cost; EPIC explicitly gates L2 on L1's metrics; skips the deterministic win for a speculative one | high |
| Global prompt-cache with TTL tuning | No repo-side artifact | Outside the kit's control; the SDK does not expose the tuning knobs the workload needs; invalidation semantics wrong for per-change work | medium |
| Include the pack in the doc-manifest's `required[]` and use `check-doc-manifest.js` for freshness | One validator instead of two | Conflates "missing mandatory document" with "stale pack"; a stale pack would block the doc-leash at the wrong gate; violates the doc-leash's single semantic (it locks on missing docs, not on stale caches) | medium |
| Include a repo-wide glob (`docs/decisions/**`) in invalidation | Any ADR edit refreshes every pack | Repo-wide rebuild on any decision edit; defeats source-scoping; forces rebuilds on unrelated changes; violates L1's per-change scope | medium |
| Allow excerpts in the pack sections | Richer content for reviewers | Excerpts drift silently — the source's sha256 stays fixed while the excerpt goes stale; defeats the invalidation guarantee; the pointers-only rule is the only way to keep byte-stability meaningful | medium |
| Write the pack imperatively per-dispatcher (each agent builds its own view) | No shared artifact to maintain | N views for the same change, all stale independently, none byte-stable across dispatches; kills the same-`subagent_type` cache reuse the SDK does grant; multiplies the maintenance surface | high |
| Include wall-clock timestamps in the pack frontmatter for auditability | Human-visible provenance | Kills byte-stability (rebuilds produce different bytes even from identical sources); kills same-`subagent_type` cache reuse; auditability is served by git blame + the telemetry JSONL, which is where timestamps legitimately live | low |
| Ship live cache/token TUI display alongside telemetry | Immediate operator feedback | Out of scope per the brainstorm's E1 resolution — belongs to a future change under [EPIC-flow-cli-ux](../roadmap/epics/EPIC-flow-cli-ux.md); coupling the two here would bloat this change and delay the L1 win | low |
