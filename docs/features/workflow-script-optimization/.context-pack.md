## DoD

- A written artifact on disk enumerates, for ALL 4 flows (full, fast, design, docs-onboarding) at equal priority, every step's type (invoke vs runs) and invoke_target, and per dispatcher (13 agents + skill-only dispatchers) its current role and whether its judgment is load-bearing or checklist-shaped — not asserted only in prose.
- Before any conversion candidate is promoted to the roadmap, at least one real flow run supplies the telemetry kwargs (--tokens-cache-read/-creation/-output) at every dispatch, and the resulting .telemetry.jsonl rollup lands in this change's evidence.md, so ADR-013/context-pack-l1's effect is measured, not assumed.
- The inventory includes, for each of the 13 agents/*.md, its body size measured on the live tree and its dispatch frequency per flow, so trim candidates are ranked by measured tokens-per-flow-run, not intuition.
- Every token/cost/percentage claim in this change's proposal/design/evidence is reproducible from a command run against the live tree it accompanies; no estimated or extrapolated number ships as a claim.
- This change's diff contains NO edits to governance/flows/*.yaml or agents/*.md; every conversion candidate and new-agent/automation idea lands as a roadmap Feature entry instead.
- Any step proposed for invoke→runs conversion is restricted to genuinely checklist-shaped judgment (file/section existence, format, count), mirroring the doc-leash/acceptance-leash/bench-leash precedent; no proposal collapses an adversarial-judgment step into a script.
- No script-replacement candidate weakens or bypasses GOVERNANCE.md §1's three human escalations (PR merge, ADR supersession, scope-beyond-approved) or the existing max_visits/human_gate escalations already wired into the flows.
- Any conversion (or new leash) a follow-up change ships is registered in a dedicated ADR before merging, never silently changed in the flow YAMLs without a decision record.
