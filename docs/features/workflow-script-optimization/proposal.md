## Why

The kit spends LLM tokens in exactly one place: an `invoke` step pausing so Claude dispatches a skill or an agent ([governance/README.md](../../../governance/README.md) §"Inversion of control"). Across the four shipped flows there are **33 `invoke` steps and 26 `runs` steps** — `full` 15/15, `fast` 9/9, `design` 5/0, `docs-onboarding` 4/2 (measured: `awk '/^  - id:/{f=1} f&&/^    type:/{print $2; f=0}' governance/flows/<f>.yaml | sort | uniq -c`). Nobody has ever written down which of those 33 dispatches buys judgment and which buys a checklist. [GOVERNANCE.md](../../../GOVERNANCE.md) §7 states the economics in one line — "the model sized to the cost (mechanical is cheap, judgment is expensive)" — and the kit has already acted on it three times (doc-leash, [ADR-010](../../decisions/ADR-010-acceptance-leash.md)'s acceptance-leash, the bench leash), each time by hand, each time from a hunch about one specific step. There is no register to work from.

The second half of the problem is that the cost is unmeasured. [ADR-013](../../decisions/ADR-013-context-pack-per-change.md) shipped the per-change context pack on 2026-07-24 with an explicit measurement promise (§Decision-7: a per-dispatch `.telemetry.jsonl`, rolled up into `evidence.md`) — and its own evidence file records `No telemetry captured for this run` ([context-pack-l1/evidence.md](../../archive/2026-07-24-context-pack-l1/evidence.md):56). It is not an isolated miss: `grep -rl '^No telemetry captured for this run' docs/` returns **2** files, and those are the only two `evidence.md` files in the repo that carry the section at all. Every claim about L1's effect — including the trigger that would promote L2 in [EPIC-context-caching](../../roadmap/epics/EPIC-context-caching.md) ("the trigger to promote L2 is data, not calendar") — currently rests on zero rows of the data the ADR designed for.

The flow authoring this very change is the first run to populate it. Three dispatches are already on disk in `.aidakit/tasks/workflow-script-optimization/.telemetry.jsonl` (`select` 125910 `cache_read` / 62356 `cache_creation` / 3747 `output`; `brainstorm` 1377529 / 397550 / 44539; `classify` all-zero). The `brainstorm` line alone reads **31× more `cache_read` than `output`** — consistent with the owner's prior finding that durable-context re-read dominates cost, and inconsistent with the intuition that step *count* is what to optimize. That is the whole reason this change is audit-only: the owner settled it at the brainstorm gate (`.aidakit/tasks/workflow-script-optimization/brainstorm.json`, axis `confrontation-with-the-law` → `measure-first`) — measure first, propose conversions second, in separate changes with their own ADRs.

A third motivator surfaced while reading the tree for this plan, and it is the concrete argument for a register over a hunch: **`classify` feeds the string `success` into `brainstorm` as its `domain`.** `full.yaml:61` interpolates `domain: "${context.classify.outcome}"` (re-measured with `grep -n 'domain:' governance/flows/full.yaml`), and the `classify` step declares no `outputs:`, so the only thing `context.classify` holds is the outcome — visible verbatim in this run's own state file (`.aidakit/flows/state/full-260725-642b02.json`, `step_history[4].output.input.domain: "success"`). This is the same defect family [ADR-006](../../decisions/ADR-006-flow-values-as-data.md) §Decision-2 closed for `select`/`change_id`, surviving one step later because nobody enumerated the steps.

## What Changes

- **A dispatch inventory lands on disk**, as one artifact in two linked files under this change's directory: `docs/features/workflow-script-optimization/inventory.md` (per-flow step tables for all four flows at equal priority — step id, `type`, `invoke_target`, back-edge/`max_visits` wiring; plus the dispatcher register with each dispatcher's role and its judgment shape, load-bearing vs checklist-shaped) and `docs/features/workflow-script-optimization/dispatch-cost.md` (the measured agent-prompt cost table). Split per [DOCS.md](../../../DOCS.md) §5's overflow rule, not by theme — `inventory.md` is the entry point and declares the relationship. Rationale for the location, and the rejected `docs/knowledge/` alternative, in [design.md](design.md) §1.
- **The cost table is measured, never estimated.** Each of the 13 `agents/*.md` gets its body size from `wc -c -w agents/*.md` on the live tree (139797 bytes / 20800 words across the 13 files, at plan time) multiplied by a **declared** dispatch-frequency metric per flow, and the ranking is that product. The metric's three tiers (static / happy-path / observed) and its lower-bound semantics are frozen in [design.md](design.md) §3–§4, because the naive count is wrong: only **5** of the 13 agents are named by any flow YAML (`orchestrator`, `brainstorm`, `spec-reviewer`, `doc-planner`, `acceptance-planner`); the other 8 reach the wire only from inside a skill's fan-out, which no `grep` over `governance/flows/` can see.
- **This run's telemetry is rolled up into `evidence.md`** by the shipped `governance/telemetry/rollup.js --change-id workflow-script-optimization`, plus a verbatim paste of the raw JSONL lines — because the rollup renderer drops two of the fields the writer persists (`output_tokens`, `duration_ms`; [governance/telemetry/append.js](../../../governance/telemetry/append.js) writes them, `renderRollupSection` in [governance/telemetry/rollup.js](../../../governance/telemetry/rollup.js) never reads them) and the JSONL itself is gitignored, so without the paste the output/duration splits die with the worktree.
- **A findings section records what the audit tripped over**, in a fixed per-finding shape (defect · mechanical evidence at `path:line` · the leash family it belongs to · where it was routed). Four findings are already in hand and named in [design.md](design.md) §6 (F1 `classify`'s outcome-as-domain, F2 the rollup's dropped fields, F3 zero-cost re-entry, F4 stale backlog declarations); the rest come from doing the pass.
- **Every conversion candidate and new-agent/automation idea lands as a roadmap Feature** in the existing epic that already owns its axis — no new epic, no conversion in this diff. Routing: leash/contract candidates → [EPIC-flow-engine-leashes](../../roadmap/epics/EPIC-flow-engine-leashes.md); prompt-trim and dispatch-cost candidates → [EPIC-context-caching](../../roadmap/epics/EPIC-context-caching.md); kit-hygiene defects → [EPIC-kit-discipline-hardening](../../roadmap/epics/EPIC-kit-discipline-hardening.md). This change also declares **itself** as a Feature under `EPIC-context-caching` (it is the measurement that ADR-013's review trigger asks for and it is currently undeclared, so the roadmap cannot see it).
- **A written selection rule gates the candidate list.** A candidate is admissible only if all five slots can be filled — the step/dispatcher, the deterministic predicate a script could evaluate, the judgment that would be LOST, the existing leash it mirrors, and the ADR the follow-up will need. A candidate that fails a slot is recorded as **rejected, with the reason**, rather than dropped silently. [design.md](design.md) §3 carries the four-question test.

## Non-goals

- **No conversion ships here.** No step changes `type`, no new validator, no new agent, no new skill. Settled by the owner at the brainstorm gate (axis `scope-deliverable` → `audit-only`), and mechanically provable: `git diff HEAD --stat` must show zero files under `governance/`, `agents/`, `skills/`, `commands/`, `hooks/`.
- **`full`/`fast` do not get priority over `design`/`docs-onboarding`.** The owner overrode the recommended default at the brainstorm gate (axis `scope-flows` → `all-4-equal-priority`). `design.yaml` (5 `invoke`, 0 `runs`, 4 `human_gate`) is in fact the extreme case of the audit's own thesis and would have been dropped by a full/fast-first cut.
- **The `classify` `domain: "success"` defect is recorded, not fixed.** It is a live contract gap in a flow YAML; fixing it here would break the audit-only invariant and skip the ADR-006-family decision it deserves.
- **The telemetry rollup's dropped fields are recorded, not fixed.** Same reason — `governance/telemetry/rollup.js` is code.
- **The 3 stale roadmap backlog declarations are recorded, not closed** (F4). This change appends Feature lines; editing or removing lines it did not author — even obviously stale ones — is roadmap surgery outside its bound, and the de-duplication needs its own change.
- **No agent prompt is trimmed.** The table ranks candidates; the trims are follow-up changes (owner decision, axis `scope-agent-prompts` → `include-in-audit`: "the trims themselves become backlog changes").
- **No new ADR.** The audit locks no decision. Every candidate it registers explicitly *requires* one before it ships (criterion `flow-shape-change-gets-adr`) — that ADR belongs to the follow-up change, not to this one.
- **Consumer repos are out of scope**, including the psim-kernel dogfooding repo (brainstorm assumption 1). The subject is the kit's own shipped flows and dispatchers.
- **No plugin version bump.** This change ships no file under `commands/`, `skills/`, `agents/`, `hooks/` or `governance/` and adds no doctrine footer, so `check-plugin-version.js` stays green without one (manifest `0.9.1` ≥ highest footer `v0.9`, measured at plan time). [PROCESS.md](../../../PROCESS.md):281-299 asks for the bump when a footer would outrank the manifest; nothing here does.
- **`ROADMAP.md`'s Portuguese prose is not translated.** The existing epics predate the kit's English-only convergence; new Feature lines are authored in English ([DOCS.md](../../../DOCS.md) §5 + no `language` field in `aidakit.config.yaml` → default `en`), and the legacy lines are left byte-identical. Translating them is a separate change nobody asked for.

## Unblocks

- **The conversion changes themselves.** Each registered candidate becomes a change with its own ADR, mirroring the [ADR-010](../../decisions/ADR-010-acceptance-leash.md) shape (dedicated writer + deterministic validator + `max_visits` from day one) rather than relocated prose. The register is what lets them be sequenced by measured cost instead of by whoever remembers a step.
- **`EPIC-context-caching`'s L2 decision.** The epic gates L2 on data, and [ADR-013](../../decisions/ADR-013-context-pack-per-change.md)'s review trigger names the exact signal ("mean per-dispatch `cache_read` stops shrinking"). A first populated rollup is the first row of that series; it does not settle L2, it makes the question answerable.
- **The `classify` structured-outputs gap**, registered as a leash candidate on `EPIC-flow-engine-leashes`. Its fix is the ADR-006 §Decision-2 pattern applied one step later (`outputs: {success: [domain]}` + a resume that carries the value), and it is worth its own change because the fail-closed re-pause semantics are a contract, not a typo.
- **Flagged, not acted on:** `skills/implement/SKILL.md`'s per-surface fan-out is a second-order dispatch site with the same accounting problem as the review bench; the inventory will name it, and whether it needs its own leash is a question for a later change. Registering it as a Feature now would be scope the owner did not ask for.
