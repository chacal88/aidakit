## Why

`agents/reviewer-quality.md` is the **second-ranked** agent prompt body by the measured ranking in [`dispatch-cost.md`](../workflow-script-optimization/dispatch-cost.md) §2: **13470 bytes / 1993 words**, ranked at **26940** on the lower-bound `body_bytes × happy_path_dispatches` metric (`13470 × 2` — it fires once on the review bench in both `full` and `fast`). Every dispatch of the agent starts a fresh isolated context that pays the full body size again; two happy-path dispatches per clean traversal make it the second-highest-leverage body to shrink, directly behind `agents/doc-planner.md` (already trimmed in the merged sibling [`trim-doc-planner-agent-prompt`](../trim-doc-planner-agent-prompt/proposal.md), `15105 → 13854`).

The reduction is *engineering*, not modelling: the win is prefix-size reduction, deterministic and independent of SDK cache hit-rate — exactly the L1 lever [ADR-013](../../decisions/ADR-013-context-pack-per-change.md) establishes ("The win we *can* engineer is **prefix-size reduction**: shrinking what each dispatch processes in the first place"). This change realises that lever on the second-ranked body by removing prose that is *redundant*, never prose that is *judgment-bearing*.

The Feature is already declared on the roadmap ([EPIC-context-caching](../../roadmap/epics/EPIC-context-caching.md) line 16, "Trim `agents/reviewer-quality.md`'s prompt body — changes: trim-reviewer-quality-agent-prompt"). Its acceptance sets the leash for this change: `wc -c -w agents/reviewer-quality.md` drops from the `13470`-byte baseline (second-ranked at `26940`), **same redundancy bar as `trim-doc-planner-agent-prompt`**, **no judgment-bearing instruction removed**; before/after byte counts recorded in this change's own evidence. The `13470`/`26940` figures in that acceptance line are the **FROM baseline** this change trims from — left intact as the baseline.

This change **mirrors the merged `trim-doc-planner-agent-prompt`** ([commit `b1ffa1c`](../trim-doc-planner-agent-prompt/proposal.md)): the same "dedupe the 3–4× restatements + drop long parentheticals, byte-preserve the frozen contract regions" recipe, and the same mandatory DNA-gate cascade on `dispatch-cost.md`. Two things differ and are called out below: (1) reviewer-quality carries **no byte-exact guard literal** — its mechanically-protected region is the **Step 0.5 context-pack block** ([`context-pack.test.mjs`](../../../governance/__tests__/context-pack.test.mjs) §6), and (2) reviewer-quality sits in a **tight ranking cluster**, so unlike doc-planner (which kept rank 1) its **rank will move down** and the §2 table re-sorts — the honest cascade this change performs.

## What Changes

- **[`agents/reviewer-quality.md`](../../../agents/reviewer-quality.md) — body-prose compression, no semantic loss.** The agent's own doctrine (the 4 phases, the 4 severities, the adversarial posture, the verdict rules) is stated **once, authoritatively**, and the 3–4× restatements of the same points across `## Role`, the blockquote, `## ADVERSARIAL posture`, `## What you decide on your own`, `## Escalation triggers`, `## What you do NOT do` and `## Output format` are compressed to pointers or dropped. Long parenthetical asides and the escalation prose that re-explains [GOVERNANCE.md §1](../../../GOVERNANCE.md) (which the caller already loads) are the primary byte savings. The **frozen contract** (4 phases, 4 severities, verdict `approved`|`rejected`, `file:line` on every finding) and the mechanically-tested **Step 0.5 context-pack block** are byte-preserved in meaning. Concrete regions and the freeze list are in [design.md](design.md).
- **[`dispatch-cost.md`](../workflow-script-optimization/dispatch-cost.md) — mandatory cascade re-measure (the DNA gate makes this non-optional).** Trimming the body changes `Buffer.byteLength`, so the [`regression-measured-body-size-tables-match-live-tree`](../../../governance/__tests__/regression-measured-body-size-tables-match-live-tree.test.mjs) DNA gate — which re-measures every fenced `wc -c -w` row against the live tree — FAILS until the `reviewer-quality` row is updated. This change re-measures on the trimmed tree and updates the live figures: the §1 fenced row (line 33, gate-enforced), the §1 `total` row (line 37, internal sum), the §2 ranking cell `26940` (line 55), the **§2 table row order** (reviewer-quality's rank drops; the table re-sorts descending), and the §2 "Reading the extremes" prose (line 70, which names reviewer-quality's `13470` as "the next largest"). It ADDS a dated trim note to §1 mirroring the existing doc-planner trim note (line 42), and PRESERVES the existing PR #54 drift note (line 40) and the doc-planner trim note (line 42) as WORM history.
- **Provenance footer** — one appended `<!-- aidakit v0.4 — … -->` line at the tail of `agents/reviewer-quality.md`, following repo convention (append, never rewrite the existing `v0.3` footer). `v0.4` is the file's next monotonic footer and stays **at or below** the plugin's highest footer (`v0.10`, on `doc-planner.md`), so it does **not** force a `plugin.json` bump (contrast the sibling, where the file's own `v0.10` footer exceeded the manifest — see Non-goals 5 and the Impact table).

## Non-goals (explicit)

1. **No behavior change to the structured verdict the bench consumes.** Not one of the 4 phases, the 4 severity labels (`blocking`/`important`/`nit`/`praise`), the verdict vocabulary (`approved`|`rejected`, one per round), or the `file:line`-on-every-finding rule is removed or altered. The frozen contract in [design.md](design.md) §"The leash" is frozen. If a candidate trim would touch any of it, it is dropped — a byte saved by weakening the contract is refused.
2. **No mechanical surface.** No validator, no test, no engine/YAML/schema/hook edit. `governance/**` is byte-identical to the merge-base. This is prose surgery on one agent file plus a measurement update on one docs file.
3. **No new ADR, no supersession.** The change is downstream of [ADR-013](../../decisions/ADR-013-context-pack-per-change.md); it records no new locked decision and contradicts none. A prompt trim changes no structure, responsibility, boundary or contract, so DOCS.md §2 requires no ADR.
4. **No spec delta.** The change touches no capability spec — `docs/specs/` does not exist in this repo (same finding as the sibling [`trim-doc-planner-agent-prompt` §Affected capabilities](../trim-doc-planner-agent-prompt/proposal.md)). It references [ADR-013](../../decisions/ADR-013-context-pack-per-change.md) without modifying it.
5. **No `plugin.json` bump expected — but verified, not assumed.** [`check-plugin-version`](../../../governance/validators/check-plugin-version.js) requires the manifest `version` to be ≥ the plugin's **highest** doctrine footer. The highest footer today is `v0.10` (on `doc-planner.md`, from the merged sibling) and the manifest is already `0.10.0`; the `v0.4` footer this change appends to `reviewer-quality.md` does not raise the highest footer, so no bump is forced. The sibling change *did* need a bump only because its file's own footer chain reached `v0.10` and overtook the manifest — not this change's situation. The implementer **runs `check-plugin-version.js .` to confirm exit 0** (the local `*.test.mjs` suite does not run it — this is the sibling's hard-won lesson, [`trim-doc-planner-agent-prompt/evidence.md` §Unresolved Deviations](../trim-doc-planner-agent-prompt/evidence.md)); if a concurrent sibling has since raised the highest footer past the manifest, that is a pre-existing condition to escalate, not silently fixed here.
6. **No target byte count invented.** Acceptance is "bytes drop from 13470 with no judgment-bearing instruction removed" — there is no fixed target. Every number recorded is one that was actually `wc`-run on the tree (measure, don't recall).
7. **No rewrite of history.** The [`dispatch-cost.md`](../workflow-script-optimization/dispatch-cost.md) line-40 drift note (the PR #54 `14752→15105` record) and the line-42 doc-planner trim note (`15105→13854`, with its snapshot "reviewer-quality's `26940`") stay verbatim as WORM history; the `proposal.md`/`design.md`/`evidence.md`/`inventory.md` of `workflow-script-optimization` are NOT touched. The `doc-planner` fenced row (line 27), total contribution, and ranking cell (line 54) are NOT touched — `doc-planner.md` is byte-identical on this tree. The [EPIC](../../roadmap/epics/EPIC-context-caching.md) `13470`/`26940` acceptance figure is the FROM baseline — left intact.
