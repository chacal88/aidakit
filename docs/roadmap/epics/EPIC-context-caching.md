# Cacheamento de contexto por change

Goal: reduzir o gasto de tokens quando o mesmo contexto durável de um change (proposal, design, tasks, ADRs, specs, DoD) é re-lido a cada dispatch de subagente. Estratégia em dois níveis: **L1** curadoria de um context pack markdown pequeno co-localizado com o change (redução determinística do tamanho do prefixo processado); **L2** cross-change (embeddings + grafo sobre `docs/knowledge/`, ADRs e archive) só depois que L1 reportar métricas empíricas.

Origem: medição do owner sobre custo real (memory `aidakit-token-cost-drivers`) — 98% do custo é `cache_read`; sessões de 8h ≈ 61% do custo total; PoC 2026-07-24 (E2 do brainstorm de `context-pack-l1`) confirmou que cross-dispatch cache hita SÓ para mesmo `subagent_type` (~59% do prefixo do SDK), então L1 vale pela redução de **tamanho** do que cada dispatch processa, não por hit-rate. Ordem: L1 primeiro (zero infra nova, mecânica simples e determinística); L2 avaliado à luz do que L1 reportar.

## Features

- **Feature:** Context pack por change (L1) — changes: context-pack-l1
  - Aceite: cada change em `docs/features/<id>/` ganha `.context-pack.md` (frontmatter `sources[]` com path + sha256 pra invalidação, 6 seções fixas — identity, decisões, ADRs, specs, code map, DoD — só ponteiros file:line, sem excertos); `aidakit:context-pack` (nova skill build/verify/rebuild) e nova fase entre `readiness` e `implement` em `full.yaml` e `fast.yaml` invalidam por hash-check escopado a `sources[]` do change (nunca glob repo-wide) e re-buildam lazy no dispatch; TODOS os dispatchers e reviewers (`implement`, `review`, `ship`, agentes `adr-reviewer`, `spec-reviewer`, `reviewer-quality`, `reviewer-security`, `reviewer-architecture`, `tester`) recebem o pack ao invés de re-ler proposal/design/tasks/ADRs; `.aidakit/tasks/<id>/.telemetry.jsonl` (append-only, gitignored) registra por dispatch `{subagent, cache_creation, cache_read, pack_size}`; `aidakit:learn` persiste distillate durável em `evidence.md` antes do worktree ser limpo; validador determinístico `governance/validators/check-context-pack.js` (contrato `AIDAKIT_GOVERNANCE`, ADR-004) garante byte-stability do pack sem conteúdo wall-clock-varying; freshness check é validador **separado** de `check-doc-manifest.js` (pack stale ≠ doc mandatory missing, nunca bloqueia doc-leash); ADR-013 registra context pack como artefato de primeira classe.

L2 (contexto cross-change via embeddings + grafo sobre `docs/knowledge/`, ADRs e archive) fica FORA do roadmap declarado até L1 reportar métricas. Trigger pra promover L2 a feature é dado, não calendário: (a) o ganho de redução-de-tamanho estagnar ou (b) dispatches precisarem de contexto de OUTROS changes com frequência que justifique embeddings.
